1. Big picture 
Pinit has two products:
Product
Role
Public?

Private owner tools: protect files, DNA, vault, share tracking, monitoring, investigation, certificates

Pinit Exchange
Public marketplace: list, buy, sell licenses

One-line rule
Exchange is only for buying and selling.
All deep protection work (DNA, vault encryption, monitoring, investigation, leak tracking) happens behind Exchange, powered by Pinit Hub. Exchange shows trust signals and sale results; Hub does the heavy forensic/ops work.
Creator protects asset in Hub        │        │  "List on Exchange"        ▼Public listing on Exchange (preview + license + DNA badge)        │        │  Buyer pays        ▼Sale sealed + license delivered        │        ▼Hub continues monitoring / investigation for that asset (behind the scenes)

3. Product goal (how Pinit Exchange should work)
Exchange should feel like a provenance marketplace, not a normal stock dump site.
Creators can
Protect assets in Hub first
List selected assets on Exchange
Set license tiers and prices
Sell to verified buyers
See sales, earnings, and activity on a creator dashboard
Rely on Hub (behind Exchange) for monitoring and investigation after sale
Buyers can
Browse / search / open requirements
See trust badges (Gold / Silver / Bronze) and DNA signals
Buy a license (not just a random file)
Receive delivery + license proof
Manage purchased licenses
What Exchange must NOT do
Open the creator’s private Hub vault to the public
Allow publishing of assets with too much AI content (see Section 9)
Replace Hub for investigation / monitoring UI for owners (those stay Hub-powered behind the scenes)
4. How Exchange connects to Pinit Hub
This is the most important architecture rule.

4.2 What “connect” means in practice
Connection
How it should work
Login
Same Pinit identity. Prefer Hub SSO / shared JWT / “Continue with Pinit Hub”. Do not invent a forever-separate user system.
Profile
Base profile comes from Pinit ID. Exchange adds public storefront + seller settings.
Billing
Seller plan + buyer checkout. Can reuse payment providers already used by Hub (e.g. Razorpay patterns).
Listing
Creator picks Hub-protected asset → Exchange creates listingId linked to Hub assetId + dnaRecordId. Vault keys never leave Hub.
Selling
Payment happens on Exchange. Delivery package is generated. Sale is stored as sealed record.
Tracking / monitoring / investigation
Triggered from Exchange events, executed by Hub services. Creator sees summary on Exchange desk; deep tools stay Hub.

4.4 Privacy boundary (never break this)
Hub vault is never a public catalog.
“List on Exchange” creates a commerce listing + preview policy, not a raw master dump.
Buyers never get Hub owner privileges.
DNA badge on Exchange is a public-safe summary, not full private forensic internals.
5. Login, profile, and billing
5.1 Login (required direction)
Current UI: email/password against a small separate backend.
Target direction:
User already has / creates a Pinit Hub account (ShortId + biometric where Hub uses it).
Exchange login: Continue with Pinit (shared session or token exchange).
If user wants to sell, unlock seller path: biometric confirmation + seller plan + KYC → mint Exchange ID.
Buyers can use lighter login for purchase friction, but still map to Pinit identity where possible.
UI/UX focus:
One clear “Log in with Pinit Hub” primary button
Secondary email path only if needed during transition
No silent dual accounts that drift apart forever

9. AI content policy and badges (mandatory)
Think like HackerRank / trust badges: clear levels buyers understand.
9.1 Publish / market rule
AI content level in image or video
Allowed on Exchange?
More than 80% AI-generated content
NO — cannot publish or market
80% AI or below
Allowed only if policy + disclosure rules pass
If AI share exceeds 80%, block publish with a clear error:
> “This asset exceeds the 80% AI-content limit and cannot be listed on Pinit Exchange.”
9.2 Human / manual authenticity badges
For assets that are allowed to list, mark by manual / human authenticity quality:
Badge
Manual / human authenticity
Meaning
Gold
About 90–100% manual / human-made
Highest originality trust
Silver
About 60–80%
Mixed / assisted but acceptable
Bronze
Lower acceptable band (below silver, still under AI reject threshold)
Entry trust tier
Notes for implementation:
Badge must be visible on cards, listing detail, and checkout.
AI-assisted vs AI-generated disclosure should stay honest.
Video and image both use the same policy family.
Hub DNA / authenticity signals should feed this badge — do not let creators self-pick Gold freely.
